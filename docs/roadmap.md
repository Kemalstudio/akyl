# Дорожная карта

Этапы из ТЗ, развёрнутые в задачи. Этап считается закрытым, когда выполнен
его критерий готовности, а не когда «в целом работает».

## Этап 1 — ядро без ML ✅

Приложение звонит и пишет SMS по введённой фразе.

- [x] Монорепо, чистая архитектура, CI
- [x] `RuleBasedNlu`: CALL, SMS, CONFIRM, CANCEL, SELECT, UNKNOWN
- [x] Поиск контакта: падежи, ласковые формы, транслитерация, Jaro-Winkler
- [x] `CallSkill`, `SmsSkill`, диспетчер диалога, контекст на 60 секунд
- [x] `PhoneBridge.kt`, `ContactsBridge.kt`, `TtsBridge.kt`
- [x] Экраны, тема, фирменный знак, иконки
- [x] Сценарии С1–С8 как тесты

**Критерий готовности:** все сценарии ТЗ зелёные, покрытие ядра ≥ 70%
(фактически 89%), `flutter analyze` без замечаний.

## Этап 2 — распознавание речи

Микрофон уже работает: команду можно сказать, текст виден по мере речи
(`DeviceSpeechStt` поверх системного движка Android, режим «только на
устройстве»). Осталось заменить чужой движок на свою модель — ради точности
на именах и ради того, чтобы гарантия офлайна была в нашем процессе,
а не в чужом. См. [speech.md](speech.md).

- [x] Запись, промежуточный текст, выполнение фразы
- [x] Голосовой ответ: выбор лучшего офлайн-голоса, мягкий темп
- [ ] Подключить `sherpa_onnx` (Flutter-пакет)
- [ ] `TOneStt implements SpeechToText`: потоковый вывод в `partialResults()`
- [ ] Передискретизация 16 кГц → 8 кГц (T-one обучена на телефонной речи)
- [ ] Silero VAD: конец фразы за 300 мс
- [ ] `ListeningService.kt`: микрофон в фоне
- [ ] Решить вопрос размера APK (docs/models.md)
- [ ] Замер бюджета на устройстве

**Критерий готовности:** от конца фразы до гудка ≤ 1000 мс на телефоне
среднего класса, замер на 30 фразах, p95.

## Этап 3 — своя NLU-модель

- [ ] Генератор датасета: 50–100 тыс. примеров с BIO-разметкой и шумом STT
- [ ] Тестовый набор: 300+ фраз живым голосом через T-one (в обучение не идут)
- [ ] Baseline: TF-IDF + логистическая регрессия
- [ ] v1: эмбеддинги + BiLSTM, две головы
- [ ] v2: трансформер с нуля, 2–4 слоя, d=128, SentencePiece
- [ ] Квантизация int8, экспорт в ONNX/TFLite
- [ ] `MlNlu implements Nlu` — те же тесты, что у `RuleBasedNlu`
- [ ] Сравнение с FunctionGemma 270M на том же наборе

**Критерий готовности:** намерение ≥ 97%, F1 по слотам ≥ 95%, задержка
≤ 20 мс p95 на телефоне, размер ≤ 5 МБ. Все сценарии С1–С8 проходят
с `MlNlu` без правок в ядре.
