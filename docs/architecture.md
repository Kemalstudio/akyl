# Архитектура

## Конвейер

```
микрофон → VAD → STT → NLU → DialogMachine → Skill → PhoneBridge (Kotlin)
                               ↕                          ↓
                         DialogContext              звонок / SMS
                          (60 секунд)                     ↓
                                                    TTS: ответ вслух
```

Фраза идёт слева направо. NLU отдаёт намерение диспетчеру, тот выбирает навык,
навык обращается к Android через Kotlin. Результат навыка превращается
в голосовой ответ и в строку истории на экране.

## Слои

| Слой | Каталог | Знает про |
|---|---|---|
| domain | `app/lib/domain/` | ничего: ни Flutter, ни Android |
| data | `app/lib/data/` | domain |
| skills | `app/lib/skills/` | domain |
| presentation | `app/lib/presentation/` | domain, skills |

`domain` не импортирует `package:flutter` вовсе. Благодаря этому сценарии
С1–С8 из ТЗ проверяются обычными юнит-тестами, без эмулятора.

## Интерфейсы

Всё, что может быть заменено, объявлено в `domain/ports/`:

| Интерфейс | Этап 1 | Дальше |
|---|---|---|
| `SpeechToText` | `DeviceSpeechStt` (движок Android, офлайн) | `TOneStt` через sherpa-onnx |
| `Nlu` | `RuleBasedNlu` | `MlNlu` — своя модель |
| `TextToSpeech` | `SystemTts` (Android) | Piper ru_RU |
| `ContactResolver` | `ContactIndex` | без изменений |
| `Phone` | `PhoneBridge` | без изменений |
| `Skill` | `CallSkill`, `SmsSkill` | новая команда = новый класс |

Сборка зависимостей — единственное место, где конкретные реализации
встречаются: `app/lib/main.dart`, функция `buildController()`.

## Конечный автомат диалога

```
idle → listening → processing ─┬→ executing → idle
                               ├→ awaitingConfirmation ─┐
                               └→ awaitingChoice ───────┤
                                                        └→ processing
```

Переходы заданы таблицей в `domain/dialog/dialog_state.dart` и проверяются
в отладочной сборке через `assert`: переход, которого нет в таблице, — ошибка
в коде, а не в речи пользователя.

Из `executing` есть возврат в `awaiting*`: навык может не выполнить команду,
а задать вопрос — «какому Ахмеду?».

## Как устроено подтверждение SMS

`SmsSkill` вызывается дважды одним и тем же объектом `NluResult`:

1. Первый раз `ctx.pendingAction == null` → навык возвращает вопрос,
   `DialogMachine` кладёт этот же объект в контекст.
2. Пользователь говорит «да» → `DialogMachine` достаёт объект из контекста
   и передаёт его навыку снова. Навык узнаёт его по `identical` и отправляет.

Так подтверждение не может «протечь» на другое сообщение: подтверждается
ровно тот объект, который был показан.

## Поиск контакта

Бюджет — 30 мс, поэтому порядок такой:

1. Точное совпадение по хеш-таблице псевдонимов.
2. Отсечение падежного окончания и повторный поиск.
3. Фонетический ключ (`Ahmet` и `Ахмед` дают один).
4. Перебор с Jaro-Winkler — только по псевдонимам близкой длины.

Индекс строится при запуске: для каждого контакта генерируются падежные формы,
ласковые формы и фонетические ключи каждой формы. Шаг 4 ограничен полосой
длин ±2 символа — без этого поиск по книге из 500 контактов занимал 250 мс
вместо 30 мс (см. `app/test/latency_test.dart`).

## Движение

Длительности и кривые заданы в одном месте — `presentation/theme/akyl_motion.dart`.
Правило одно: элемент приходит снизу с проявлением, уходит на месте, гаснув.

| Токен | Время | Где |
|---|---|---|
| `instant` | 160 мс | смена значка, подсветка рамки |
| `quick` | 260 мс | появление реплики, смена подписи |
| `base` | 380 мс | переходы состояний экрана, прокрутка |
| `slow` | 520 мс | смена экрана целиком |

Кривая появления — `Cubic(0.16, 1, 0.3, 1)`: быстрый старт и долгое мягкое
торможение. Линейная кривая на тех же длительностях выглядит механической.

Два готовых приёма покрывают почти всё:

- `FadeSlideIn` — появление снизу; `delay` выстраивает элементы цепочкой,
  чтобы экран собирался, а не вспыхивал целиком;
- `SoftSwitcher` — мягкая замена содержимого; уходящее и приходящее лежат
  друг на друге и не толкаются.

Ассистент отвечает за доли секунды. Если интерфейс при этом дёргается,
быстрым он не ощущается — поэтому движение здесь не украшение.

## Kotlin

Kotlin отвечает только за системные вызовы, вся логика решений — в Dart:

| Канал | Файл | Что делает |
|---|---|---|
| — | `VoiceEngine.kt` | один движок Flutter на процесс: Dart живёт без экрана |
| `dev.akyl/mic` | `MicHub.kt` | единственный `AudioRecord`, 16 кГц, AEC/NS, «запись заглушена» |
| `dev.akyl/voice` | `VoiceBridge.kt` | служба микрофона, блокировка, звонки, сигнал «слушаю» |
| — | `VoiceService.kt` | foreground-служба microphone с уведомлением |
| — | `AssistantVoiceService.kt` | роль помощника: запуск после перезагрузки |
| `dev.akyl/phone` | `PhoneBridge.kt` | разрешения, `TelecomManager.placeCall`, `SmsManager` |
| `dev.akyl/contacts` | `ContactsBridge.kt` | чтение `ContactsContract` |
| `dev.akyl/device` | `DeviceBridge.kt` | будильник, таймер, фонарик, громкость, плеер, журналы |
| `dev.akyl/tts` | `TtsBridge.kt` | системный `TextToSpeech`, аудиофокус, ритм слов |

Звонок идёт через `TelecomManager.placeCall`: он не запускает экран и
поэтому работает из фона и с заблокированного телефона.

Голосовой конвейер целиком — в [voice.md](voice.md).
