# Голос: обращение «Макс», фон, разговор

Документ описывает голосовой конвейер после переделки 29.09.2026. Прежнее
состояние и найденные тогда ошибки — [voice-audit-2026-09-29.md](voice-audit-2026-09-29.md).

## Почему прежний вариант не работал

| Симптом | Корневая причина |
|---|---|
| Микрофон «щёлкал», включался сам после выхода из приложения | Фоновый режим был циклом системного `SpeechRecognizer`: сеанс ~10 с → стоп → перезапуск. Каждый перезапуск — системный сигнал и индикатор микрофона. В `dumpsys audio` телефона видны сеансы `com.google.android.as` каждые 10–12 с |
| «Макс» не слышен, если сказать его в паузе | Между сеансами распознавателя микрофон закрыт |
| В свёрнутом приложении запись «шла», но ничего не слышала | `AudioRecord` без foreground-службы типа microphone Android заглушает: в `dumpsys audio` запись помечена `silenced`, поток — нули |
| Команда в фоне требовала открыть приложение | Весь Dart (диалог, навыки) жил в движке Flutter внутри `MainActivity` и умирал вместе с экраном |
| Гонки, двойные слушатели, рассинхрон UI | Два владельца микрофона — Dart-цикл и Kotlin-служба — договаривались флагами «пауза»; запись закрывалась и открывалась после каждой фразы |

## Как устроено теперь

```
MicHub.kt (один AudioRecord на процесс, 16 кГц, окна 32 мс, AEC/NS по настройке)
   │  EventChannel dev.akyl/mic
   ▼
ToneVoicePipeline ─► изолят voice-pipeline ─► PipelineCore
                                              ├ Silero VAD — всегда, ~0.3 мс на окно
                                              ├ T-one — только на речь
                                              ├ WakeMatcher — «Макс» в первых словах
                                              └ конец фразы по тишине VAD (700 мс)
   │  события с номером режима (epoch)
   ▼
VoiceManager — единственный владелец голоса
   ├ фаза: disabled → listeningForWake → listeningForCommand → processing → speaking → …
   ├ сверка «желаемое ↔ фактическое» строго по очереди: микрофон, служба, режим
   ├ разговор без повторного «Макс» (5–30 с), перебивание ответа
   └ AssistantController → DialogMachine → навыки → Kotlin (звонок, SMS, будильник…)
                                                     │
                                       SystemTts ◄───┘ ответ голосом, фокус с приглушением
```

Процессный движок Flutter (`VoiceEngine.kt`) создаёт тот, кто первым
попросил: экран или служба микрофона. Экран к нему только подключается и
не уничтожает при закрытии. Поэтому после перезагрузки, с заблокированным
экраном и при убранной из недавних задаче работает весь стек, а не только
микрофон.

### Состояния

```
DISABLED ─► STARTING ─► LISTENING_FOR_WAKE ─► WAKE_DETECTED ─► LISTENING_FOR_COMMAND
                               ▲                                        │
                               │        SPEAKING ◄── PROCESSING ◄───────┘
                               │           │  (перебили — снова LISTENING_FOR_COMMAND)
                               └───────────┘  (тишина после продолжения)
ERROR ◄─ фатальный сбой (нет разрешения)
RECOVERING ─► повтор через 1, 2, 4… 30 с ─► LISTENING_FOR_WAKE
PAUSED ─ звонок · микрофон занят другим приложением · фон без службы
```

Каждая смена режима конвейера получает номер. Событие со старым номером
отбрасывается: запоздавший результат прошлой фразы не может выполнить
команду или закрыть новую.

### Обращение: почему не отдельная KWS-модель

Сравнение на реальной платформе проекта (офлайн, без `INTERNET`, русский):

| Вариант | Итог |
|---|---|
| Porcupine | Требует AccessKey и сетевую проверку — противоречит офлайн-гарантии |
| openWakeWord | Готовые модели английские; обучение своей требует русского TTS-конвейера |
| sherpa-onnx KWS (gigaspeech 3.3M) | Проверено на синтезированном русском «Макс»: при пороге 0.12 — 3 из 10 срабатываний и ложные на «Максим», «Максимально». Русской KWS-модели в релизах нет |
| Vosk grammar | Ещё одна модель и нативная библиотека рядом с T-one |
| whisper.cpp | Слишком тяжёл для постоянного прослушивания |
| **VAD + T-one + фонетическое сопоставление** | Уже в APK, русская, в процессе приложения. Выбрано |

T-one распознаёт короткое имя с ошибками. Эти ошибки замерены: русская речь
Piper в 36 вариантах темпа дала «макс, мак, маг, магс, матс, мах, мась,
нась, насть, натс, нас, над». `WakeMatcher` ищет их общий звуковой рисунок
(носовой + «а» + смычный и/или «с») и принимает неточную форму, только если
за ней начинается команда («нась позвони маме») или фраза — одно слово.
«Нас позвали в гости», «над городом», «Максим пришёл» не будят помощника.

Результаты теста на настоящих моделях (`test/data/voice_pipeline_model_test.dart`):

| Сценарий | Результат (серия прогонов) |
|---|---|
| «Макс, команда» одной фразой, 12 синтезов | 8–12 из 12 |
| «Макс.» — пауза — команда, 12 синтезов | обращение 5–8 из 12 |
| Речь без обращения, 24 фразы (в т. ч. «Максим», «нас», «мак», «над») | 0 ложных срабатываний |
| Обращение от начала речи | ≈1.2 с (включая само слово) |
| Расшифровка команды T-one | ≈0.2–0.27 с процессора на фразу (ПК) |

### Обучение своему голосу

Одиночное «Макс» с паузой — слабое место любой модели распознавания:
T-one пишет короткое слово без контекста пустой строкой, «н», «на» или
«нас». Поэтому в настройках голоса есть «Мой голос для «Макс»»: три
записи имени. Короткое одиночное слово, которое T-one не расшифровала
(или расшифровала как «н…»/«м…»), сравнивается с образцами по звучанию:
MFCC (12 коэффициентов, 10 мс) + DTW, порог — по разбросу самих образцов.
Ясно другое слово («да», «так») не проверяется вовсе.

| Одиночное «Макс.» → пауза, 12 синтезов | Результат (4 прогона) |
|---|---|
| Без обучения | 5–7 из 12 |
| С обучением на 3 образцах | 9–12 из 12 |
| Одиночные «да, так, нет, мама, Максим, алло, вакс, нас» | 0–2 ложных из 16 |

Хранятся отпечатки MFCC, а не запись голоса, и только на телефоне.
Сравнение считается за доли миллисекунды и только для коротких фраз.

Piper синтезирует со случайным шумом, поэтому каждый прогон — новое
произношение; отсюда диапазоны. Без шума речь монотонная и распознаётся
хуже живой (одиночное «Макс» — 3 из 12), поэтому шум оставлен.

Синтез — не живой голос: на телефоне цифры будут другими. Надёжнее всего
звучит имя сразу с командой или «Привет, Макс».

### Экономия батареи

- Тишина стоит только Silero VAD (одно окно 32 мс — доли миллисекунды).
- T-one включается на речь и в режиме ожидания расшифровывает не больше
  2.5 с каждой фразы: если имени в начале нет, дальше — чужой разговор
  или телевизор, и модель молчит до паузы.
- Микрофон не переоткрывается между фразами.
- Громкость для анимации шлётся из изолята, только пока экран виден.
- Анимация знака в покое — 30 кадров в секунду, в фоне кадров нет вообще.

Расход за час ожидания на Samsung A17 ещё не измерен (см. «Проверка на
телефоне»).

### Ответ голосом и перебивание

- Пока звучит ответ, конвейер переходит в `muted` (перебивание выключено)
  или `bargeIn`: тогда он ищет только «Макс». Голос ответа имени не
  содержит, поэтому сам себя не перебивает.
- С включённым подавлением эха (источник `VOICE_COMMUNICATION` +
  `AcousticEchoCanceler`) перебить можно просто речью.
- После ответа 250 мс тишины: хвост звука в комнате не будит VAD.
- TTS берёт аудиофокус `GAIN_TRANSIENT_MAY_DUCK`: музыка стихает, а при
  входящем звонке ответ сразу замолкает.

## Фоновый режим

1. «Откликаться на обращение» — микрофон открыт, пока экран приложения виден.
2. «Слушать, когда приложение закрыто» — запускается `VoiceService`
   (foreground, тип microphone, уведомление с кнопкой «Выключить»). Пока он
   работает, Android не заглушает запись: слушает в свёрнутом приложении,
   с выключенным и заблокированным экраном, после удаления из недавних.
3. «Помощник Android» (выбор Alym AI в системных настройках) нужен для
   перезагрузки: Android сам привязывает `VoiceInteractionService`, а ему
   разрешено запускать microphone-службу из фона.

### Ограничения Android — честно

| Что | Почему |
|---|---|
| После перезагрузки без выбора помощником — не слушает, пока не откроете приложение | Android 14+ запрещает запуск microphone-службы из фона, `BOOT_COMPLETED` тоже не может её запустить ([документация](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start)) |
| До первой разблокировки после загрузки — не слушает | Данные приложения (модели, настройки) зашифрованы до ввода PIN; служба стартует по `ACTION_USER_UNLOCKED` |
| «Принудительно остановить» в настройках — не слушает до открытия | Так Android останавливает любое приложение |
| Samsung «спящие приложения», агрессивная экономия | Может убить службу. В настройках голоса — статус оптимизации батареи и кнопка исключения |
| Во время звонка не слушает | Микрофон у телефонии; после звонка ожидание возвращается само |
| Другое приложение записывает звук | Android заглушает нашу запись; экран показывает «микрофон занят», без переоткрытий |
| Личное с заблокированного экрана | По умолчанию SMS, журнал звонков и память читаются только после разблокировки; звонки, время, будильники, напоминания — сразу |

## STT и языки

Основной движок — T-one (русский, 8 кГц, в процессе приложения). Если модель
не загрузилась, кнопка микрофона работает через системное распознавание
Android в режиме «только на устройстве»; обращение «Макс» тогда недоступно.
Туркменские команды понимает NLU (`turkmen_commands.dart`), но офлайн-модели
туркменской речи нет. Английский NLU не поддерживает — переключатель языка
не добавлен, чтобы не обещать несуществующее.

## Навыки (tool routing)

Интерфейс `Nlu` → `Intent` → `Skill` и есть маршрутизатор инструментов:
намерение с разобранными слотами вызывает ровно один навык, ответ
произносится. LLM не подключён: приложение офлайн и без `INTERNET`, а
ключ провайдера в APK положить нельзя. Для облачной модели нужен свой
backend с временными ключами и отдельное решение о приватности.

### Проверка на телефоне

logcat показывает события без текста речи:

```bash
adb logcat -s AkylVoice flutter
adb shell dumpsys audio | grep -E "rec (start|stop|update)"   # ни одного silenced, пока служба работает
adb shell dumpsys activity services dev.akyl.akyl | grep VoiceService
```

Панель «Отладка голоса» (Настройки → Голос и обращение) показывает фазу,
источник звука, AEC/NS, службу, задержки и журнал.
