# Аудит голосового конвейера Alym AI — 29 сентября 2026

## Фактическая архитектура

Приложение — Flutter/Dart с Android-мостами на Kotlin. Backend, авторизации,
облачного LLM и выбора моделей в нём нет. Диалог разбирается `RuleBasedNlu`,
навыки запускают локальные действия телефона. Для STT сначала используется
T-one через sherpa-onnx с Silero VAD; при невозможности загрузки модели
применяется системный Android STT. Ответ произносит Android TextToSpeech.

Сейчас есть два режима ожидания обращения:

| Режим | Владелец микрофона | Когда работает |
| --- | --- | --- |
| Открытое приложение | `AssistantController` → `ToneStt` → `MicBridge` | Только после включения «Откликаться на Макс»; закрывается при уходе UI в фон |
| Свёрнутое приложение | `WakeListeningService` → локальный `SpeechRecognizer` | Только после отдельного включения, выбора системного помощника и разрешения микрофона; экран должен быть разблокирован |

Оба режима ищут «Макс» в распознанной фразе. **Ни один из них пока не является
отдельным детектором ключевого слова.** Фоновый режим последовательными
сеансами `SpeechRecognizer` может пропускать фразы между сеансами, издавать
системные сигналы и расходовать батарею. Android прямо не рекомендует
`SpeechRecognizer` для непрерывного распознавания:
[документация API](https://developer.android.com/reference/android/speech/SpeechRecognizer).

## Найденные причины сбоев и исправления

1. Значение по умолчанию у `wake_word_in_app` было `true`; после первого
   запуска `AssistantController.init()` открывал микрофон без действия
   пользователя. Теперь значение по умолчанию `false`.
2. Переключатель ожидания в открытом приложении автоматически синхронизировал
   фоновую службу. Это могло создать неожиданный постоянный режим после
   закрытия UI. Автоматическая синхронизация удалена: режимы включаются
   независимо.
3. `ToneStt` держал подписку на микрофон ещё две секунды после конца фразы.
   Теперь он закрывает её сразу, а `finalResult()` дожидается освобождения
   микрофона перед TTS или следующим сеансом.
4. `MicBridge` мог оставить поток чтения после отмены подписки или создать
   новый `AudioRecord`, пока предыдущий ещё закрывался. Теперь мост
   останавливает прежний recorder, ждёт поток с ограничением по времени,
   отвергает новую запись при задержке освобождения и отбрасывает устаревшие
   аудиокадры. `MainActivity` закрывает мост при уничтожении UI.
5. При отзыве разрешения или ошибке чтения `AudioRecord` мог аварийно
   завершить работу или крутиться на отрицательных кодах чтения. Эти ошибки
   теперь завершают сеанс и передаются в Dart.
6. Отказ загрузки T-one оставлял `ReceivePort` открытым. Порт и isolate теперь
   освобождаются и при неудачной инициализации.
7. Фоновый режим раньше мог перейти с локального движка на сторонний
   распознаватель, несмотря на `EXTRA_PREFER_OFFLINE` (это лишь предпочтение).
   Теперь он требует `createOnDeviceSpeechRecognizer` и останавливается,
   если локального движка нет.
8. Наблюдатель жизненного цикла находился только в `HomeScreen`. Он перенесён
   в корень приложения, поэтому закрытие экрана приветствия и смена экрана
   также передают состояние в контроллер. При уходе UI активная запись
   команды останавливается; фоновая служба возобновляется после её освобождения.
9. Финальный результат старого T-one сеанса мог прийти после нового `start()`
   и ошибочно завершить свежую команду. Команды и ответы isolate теперь несут
   идентификатор сеанса; устаревшие результаты и кадры отбрасываются.
10. В открытом приложении восемь секунд тишины завершали ожидание «Макс»,
    вызывая повторное открытие `AudioRecord` и возможный системный звук.
    Теперь при ожидании тишина не закрывает запись; VAD пропускает её без
    декодирования T-one. Ручная команда по-прежнему имеет тайм-аут тишины.

## Возможности и ограничения

- Примеры «какое сегодня число», «позвони маме» и напоминания проходят через
  правила NLU и существующие навыки. Звонок требует разрешения и поиска
  контакта; SMS подтверждается перед отправкой. Это не LLM tool calling.
- TTS останавливается до нового распознавания. Автоматическое продолжение
  диалога есть для вопросов подтверждения; полноценный barge-in и потоковый
  синтез пока отсутствуют.
- На Android 14+ запуск microphone foreground service из фона ограничен;
  выбранный пользователем `VoiceInteractionService` имеет специальное
  исключение. Служба не обходит блокировку экрана и не запускается после
  принудительной остановки приложения. См.
  [ограничения Android](https://developer.android.com/develop/background-work/services/fgs/restrictions-bg-start).
- Для настоящего локального «Макс» нужен валидированный русский KWS-модельный
  файл и замеры ложных срабатываний/пропусков на телефоне. У sherpa-onnx есть
  Android KWS, но опубликованные модели в его документации — английские и
  китайские: [sherpa-onnx KWS](https://k2-fsa.github.io/sherpa/onnx/kws/index.html).
  openWakeWord в основной документации заявляет только английский:
  [openWakeWord](https://github.com/dscripka/openWakeWord).
  Porcupine поддерживает русский и Android, но требует AccessKey и сетевую
  проверку; нельзя положить секрет в APK и сохранить текущую офлайн-политику:
  [Porcupine Android](https://github.com/Picovoice/porcupine/blob/master/binding/android/README.md).
- Расход батареи, задержка и качество пробуждения не измерены. 60 fps UI и
  поведение Bluetooth/звонков не подтверждены автоматическими тестами.
- Встроенного LLM, облачного API, календаря и model selector нет. Добавлять
  видимый «выбор модели» без работающих моделей было бы вводящим в заблуждение.
- В `build.gradle.kts` release-вариант пока подписывается debug-ключом.
  Сборка пригодна для установки и проверки, но для публикации требуется
  отдельная release-подпись.

## Проверки

`flutter analyze`: ошибок нет. `flutter test`: 217 тестов прошли. Они
проверяют включение/выключение ожидания, возврат из фона, команды, навыки,
контакты, историю и снимки UI. Release APK для arm64 успешно собран; в его
манифесте нет разрешения `INTERNET`. Debug APK не собрался из-за отсутствующих
в кэше Flutter engine JAR и недоступного DNS `storage.googleapis.com`.
После оптимизации тишины повторно прошли 15 целевых тестов голосового режима,
а анализатор снова не нашёл ошибок.

Release APK установлен поверх текущей версии на Samsung A17 с Android 16.
Приложение открылось в переднем плане, процесс остался жив и в logcat не было
фатальных ошибок приложения. Устройство уже имело выбранного системного
помощника и включённую фоновую службу; данные и настройки сохранились.
Акустическое срабатывание, экран блокировки, Bluetooth и расход батареи
этой проверкой не доказаны. Звонки и SMS при проверке не запускались.
